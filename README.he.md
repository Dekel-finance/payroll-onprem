# מערכת השכר — התקנה בשרת שלכם

כל מה שהמערכת צריכה, רץ על שרת בבעלותכם: מסד הנתונים, קונסולת השכר, הניהול,
סוכן האוטומציה, והמחבר שמפעיל את מיכפל על מכונת Windows במשרד.

**שום נתון שכר לא יוצא מהבניין.** התהליך היחיד עם גישה לאינטרנט הוא שער
(gateway) שמחליף ערכים מזהים בסימנים חלופיים לפני שטקסט כלשהו מגיע לספק המודל,
ומחזיר את הערכים האמיתיים לתשובה. האפליקציות יושבות על רשת Docker שאין לה מסלול
החוצה כלל — לא בגלל מדיניות אלא במבנה: קריאה שתעקוף את השער פשוט לא תצליח
להתחבר.

## לפני שמתחילים

| | מינימום | מומלץ |
|---|---|---|
| מעבד | 4 ליבות | 8 ליבות |
| זיכרון | 8 ג׳יגה | 16 ג׳יגה |
| דיסק | 40 ג׳יגה פנויים | 100 ג׳יגה SSD |
| מערכת הפעלה | לינוקס עם Docker Engine 24+ ו-Compose v2.20+ | Ubuntu 22.04 / 24.04 LTS |

בנוסף צריך:

- **אין שום גישה נכנסת מהאינטרנט**, ו**גישה יוצאת ב-HTTPS לארבעה יעדים לכל
  היותר** — הכניסו אותם לרשימת ההיתר ליציאה וחסמו את השאר:

  | יעד | לשם מה | הכרחי |
  |---|---|---|
  | `dekelmichpalil.azurecr.io` | תמונות התוכנה | **כן** |
  | `dekel.sh` | ההתקנה מדווחת על תקינותה ומושכת את דואר הנכנס | **כן** |
  | `broker.dekel.io` | AI, שאליו ניגש רק השער | רק עם יכולות AI |
  | נקודת הדיווח שלכם | טלמטריה מצרפית | לא — ריק לא שולח דבר |

  יש **שני ספקי AI, לא אחד**. רשימת היתר או מרשם עיבוד שמזכירים רק את הספק
  המוכר אינם שלמים.
- **מפתח לספק המודל**, או שנספק אחד.
- *לא חובה:* **מכונת ה-Windows שמריצה מיכפל**, נגישה מהשרת הזה בפורט 3389. בלעדיה
  כל השאר עובד; המחבר פשוט לא יעלה.

בדקו את המכונה לפני שמתקינים משהו:

```bash
./install.sh check
```

הפקודה מדווחת מה חסר ולא כותבת דבר.

## התקנה

```bash
git clone https://github.com/Dekel-finance/payroll-onprem.git
cd payroll-onprem

./install.sh install
```

ההתקנה מבקשת כתובת דוא״ל וסיסמה למנהל הראשון, ואז מדפיסה את שלוש הכתובות
לפתיחה. זה לוקח בערך חמש דקות, רובן הורדה.

**ההתקנה עולה ריקה** — בלי לקוחות, בלי עובדים, בלי תלושים. הרשומות שלכם נכנסות
דרך תהליך הקליטה והסנכרון ממערכת השכר. התקנה שהייתה מגיעה מלאה מראש הייתה
משאירה לכם שורות שצריך לזהות ולמחוק לפני שאפשר לסמוך על משהו שרואים במסך.

### מה נכתב

קובץ אחד, `.env`, שמחזיק את הסודות של ההתקנה הזו.

> **גבו את `.env` למקום שאינו המכונה הזו, לפני שממשיכים.**
> שניים מהמפתחות בו מצפינים נתונים במנוחה: אחד מצפין כל מסמך של עובד, והשני הוא
> מה שמאפשר לקרוא מספר תעודת זהות. אם הקובץ אובד, אי אפשר לשחזר את הנתונים —
> לא אנחנו ולא אף אחד אחר. זה התכנון, וזה גם בלתי הפיך.

| קונסולה | `https://<השרת-שלכם>` | לשכת השכר |


### אזהרת האישור, ולמה היא שם

בכניסה הראשונה הדפדפן יזהיר שהאישור אינו מהימן. הוא הונפק על ידי רשות אישורים
קטנה שרצה בתוך ההתקנה שלכם, מפני שרשות ציבורית כמו Let's Encrypt לא יכולה
להנפיק אישור לשם ברשת פרטית — היא חייבת להגיע לשרת מהאינטרנט, וזה בדיוק מה
שההתקנה הזו נמנעת ממנו.

מתקנים פעם אחת, בכל מחשב. ייצוא אישור השורש:

```bash
docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt .
```

ואז התקנה שלו כרשות שורש מהימנה:

- **Windows** — לחיצה כפולה על `root.crt` ← התקן אישור ← מחשב מקומי ← מקם את כל
  האישורים בחנות הבאה ← **רשויות אישורים מהימנות (Trusted Root)**. אפשר להפיץ
  לכל המחשבים בבת אחת דרך Group Policy.
- **macOS** — פתיחה ב-Keychain Access ← System ← לסמן *Always Trust*.
- **לינוקס** — להעתיק ל-`/usr/local/share/ca-certificates/` ולהריץ
  `sudo update-ca-certificates`.
- **iOS / Android** — לשלוח את הקובץ במייל למכשיר ולהתקין כפרופיל.

HTTP רגיל אינו אפשרות, ושווה להבין למה: האפליקציות מסמנות את עוגיית ההתחברות
כ-`Secure`, ודפדפנים משליכים עוגייה כזו כשהיא מגיעה דרך `http://`. מעל HTTP דף
ההתחברות יקבל את הסיסמה, יעביר אתכם, ויחזיר אתכם לדף ההתחברות — לנצח, בלי שגיאה
בשום מקום.

אם לשרת יש שם מתחם ציבורי, הגדירו אותו ב-`SITE_ADDRESS` ובחרו
`CADDYFILE=Caddyfile.public` בקובץ `.env`, ואישור רגיל יונפק אוטומטית. פורט 80
חייב להיות נגיש לצורך הבדיקה.

### פתיחת הפורט

החבילה מפרסמת שני פורטים בלבד:

| פורט | למה | מי צריך להגיע |
|---|---|---|
| **443** | הקונסולה | הצוות שלכם, מתוך הרשת |
| **80** | חידוש התעודה | רק אם `<השרת-שלכם>` הוא שם ציבורי |

שום דבר לא צריך להיות נגיש **מהאינטרנט**.

```bash
sudo ufw allow 443/tcp
sudo ufw allow 80/tcp
```

פורט הניהול אינו ברשימה במכוון — הוא מוגבל ל־`127.0.0.1`, ושום כלל חומת אש
לא ישנה זאת.

## חיבור מיכפל

המחבר מפעיל את מיכפל דרך RDP על מכונת Windows ברשת שלכם.

המחבר אינו רץ על השרת הזה. הוא מפעיל את מיכפל מרחוק, מהתשתית שלנו, ולכן
אין מה להתקין כאן והמכונה הזו אינה צריכה גישה למחשב ה־Windows.

אם נבקש מכם להגדיר `MICHPAL_WORKER_URL` ו־`WORKER_TOKEN` בקובץ `.env` —
אלו הכתובת והמפתח של אותו מחבר, בגישת HTTPS ככל שירות חיצוני אחר.

הרצה אחת בכל רגע, במכוון: מכונת Windows נותנת סשן אינטראקטיבי אחד למשתמש, ושתי
אוטומציות שחולקות שולחן עבודה אחד מפריעות זו לזו באופן שיקר לתקן.

> **האוטומציה מכוילת מול התקנת מיכפל שלנו.** היא מזהה מסכים לפי הפיקסלים שלהם,
> ולכן גרסה אחרת, רזולוציה אחרת או ספר חברות אחר עשויים לדרוש כיול מחדש. עדיף
> לתאם איתנו פגישה לכך מראש ולא לגלות את זה באמצע הרצת שכר.

## עדכונים

ההתקנה בודקת אם יצאה גרסה חדשה **כל עשר דקות** ומחילה אותה בעצמה. אין מה להריץ.

היא עוקבת אחרי ערוץ `stable` — הגרסה שאישרנו, ולא מה שנבנה לאחרונה — כך שעדכון
קורה רק כשהחלטנו שכן. מה שמופעל מחדש מוגדר בכוונה בצמצום:

| | מתעדכן לבד |
|---|---|
| האפליקציות (קונסולה, ניהול ושירותי הרקע) | **כן** — כמה שניות לכל אחת, אחת בכל פעם |
| מסד הנתונים | **אף פעם.** שדרוג מסד נתונים הוא מיגרציית נתונים, ולא משהו שעושים ללא השגחה בשלוש לפנות בוקר. |
| המחבר למיכפל | **לא**, כברירת מחדל. הוא מריץ סשן אחד בכל רגע ושומר את מצב ההרצה בזיכרון, כך שהפעלה מחדש באמצע הרצה הייתה מסיימת את הרצת השכר בלי לדווח. `./install.sh update` מפעיל אותו מחדש כשאתם צופים. |

**כדי לאשר כל עדכון בעצמכם**, הגדירו אחד מאלה בקובץ `.env` והפעילו מחדש:

```bash
AUTO_UPDATE_MONITOR_ONLY=true   # reports what it would do, changes nothing
BUNDLE_VERSION=1.1.6            # pin an exact version; updates never fire
```

בשני המקרים `./install.sh update` מחיל את הגרסה הנוכחית מיד.

> מנגנון העדכון צריך גישה לשירות ה-Docker במכונה, מה שהופך אותו בפועל למורשה
> כמו חשבון המנהל. זה המחיר של עדכוני אבטחה ללא השגחה על שרת שאף אחד לא מתחבר
> אליו. אם מדיניות האבטחה שלכם לא מאפשרת זאת, השתמשו ב-`AUTO_UPDATE_MONITOR_ONLY=true`
> ועדכנו ידנית.

## תפעול שוטף

```bash
./install.sh status     # what is running, and the addresses
./install.sh logs       # follow everything; ./install.sh logs console for one service
./install.sh backup     # database + documents, into ./backups/<timestamp>/
./install.sh update     # pull a new release and restart
./install.sh stop       # stop; the data is untouched
```

### גיבויים

`./install.sh backup` כותב שני קבצים: דאמפ של מסד הנתונים וארכיון של המסמכים
השמורים. צריך את שניהם — שחזור של מסד הנתונים בלי המסמכים נותן התקנה שבה כל
העובדים קיימים ואף קובץ שלהם לא נפתח.

אף אחד מהם אינו קריא בלי `.env`. שמרו את העותק ההוא במקום אחר: ארכיון שיושב ליד
המפתח שמצפין אותו הוא גניבה אחת, לא שתיים.

## מה יוצא מהרשת שלכם

שלושה דברים, ולא יותר:

1. **בקשות למודל**, דרך השער, כשערכים מזהים מוחלפים בסימנים
   (`[PII:ID:1]`) ומוחזרים בתשובה. מסמכים נקראים *על השרת הזה* — קובץ PDF הופך
   לטקסט כאן, ורק הטקסט המוסווה חוצה. מה שסריקה לא מוסרת ל-OCR נדחה ולא מועבר.
2. **טלמטריה מצטברת**, אם תפעילו אותה: מונים, משכי זמן, קודי שגיאה ומזהים
   מגובבים, כדי שנוכל לראות שההתקנה תקינה. היא נבדקת מול רשימת היתר בדיוק לפני
   השליחה — כל דבר שאינו מספר, חותמת זמן, גיבוב או קוד מוכר נדחה, כך שבמבנה אין
   דרך ששם או הודעת שגיאה שמצטטת מסך יעברו. הכתובת `GET /snapshot` בשירות
   המדדים מראה לכם בדיוק מה היה נשלח. אם משאירים את `BETTERSTACK_*` ריק, לא
   מדווח דבר.
3. **הורדות תמונות**, בהתקנה או בעדכון.

אין ערוץ גישה מרחוק. אנחנו לא יכולים להיכנס להתקנה הזו; אם תרצו שנסתכל על משהו,
אתם שולחים לנו את מה שאתם בוחרים לשלוח.

## כשמשהו לא עובד

```bash
./install.sh logs <service>
```

| התסמין | איפה לבדוק |
|---|---|
| דף ההתחברות חוזר לעצמו | אתם על `http://`. ראו את פרק האישור למעלה. |
| ״להקצות מחבר״ בפעולת מיכפל | עדיין לא הוקצה מחבר ללשכה הזו — פנו אלינו ונחבר אחד למיכפל שלכם. |

| המודל דוחה מסמך | `GATEWAY_ATTACHMENTS=block` וה-OCR לא הצליח לקרוא את הסריקה. סריקה ברורה יותר, או שינוי מודע ל-`allow`. |
| תזכורות לא נשלחות | `./install.sh logs scheduler` — הוא מחזיר 503 כשמשימה הפסיקה להצליח. |

תמיכה: **support@dekel.finance**. צרפו את הפלט של `./install.sh status` ואת מזהה
ההתקנה מתוך `.env` (`METRICS_INSTALL_ID`).
