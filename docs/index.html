Installation guide

Run the payroll platform on your own server

The database, the console, the back office, the employee portal and the מיכפל connector — all on hardware you own. About twenty minutes, most of it downloading.

What you are installing

Ten containers on one machine. The six that hold your data — the console, the back office, the portal, the agent, the scheduler and the database — sit on a Docker network with no route to the internet at all: not as a policy, but as a fact of how the network is built. A call that tried to skip the gateway would fail to resolve rather than leak. Only four containers can reach out at all — the gateway, the telemetry reporter, the certificate proxy and the updater.

Identifying values are replaced before anything leaves, and restored in the answer.

Before you start

 MinimumComfortable
CPU4 cores8 cores
RAM8 GB16 GB
Disk40 GB free100 GB SSD
OSLinux, Docker Engine 24+, Compose v2.20+Ubuntu 22.04 / 24.04 LTS

Outbound HTTPS to exactly two hosts, and no inbound access from the internet at all:

  • dekelmichpalil.azurecr.io — where the software is downloaded from.
  • api.anthropic.com — the model vendor, reached only by the gateway.

No credentials are needed to download the software — the images are served publicly and carry no source code. You will need a model vendor key (or ask us to supply one), and — only if you want the connector — the Windows machine running מיכפל, reachable from this server on port 3389.

01

Check the machine

This writes nothing. It reports what is missing and stops.

# download the kit
git clone https://github.com/Dekel-finance/payroll-onprem.git
cd payroll-onprem

./install.sh check

It checks Docker and Compose versions, cores, memory, free disk, the two hostnames above, and whether the three ports are free. Anything marked ! has to be fixed first.

02

Install

./install.sh install

It asks for an email address and a password for the first administrator, then prints the three addresses to open. Running it again is safe — it repairs a half-finished install rather than starting a second one.

The install comes up empty

No clients, no employees, no payslips. Your records arrive through onboarding and the sync from your payroll system. An install that arrived pre-filled would be rows you had to identify and delete before you could trust anything on the screen.

03

Back up the key file

The installer writes one file, .env, holding this install's secrets.

Do this before you go further

Two of the keys in .env seal data at rest: one encrypts every employee document, the other is what makes an identity number readable. If the file is lost, the data in the volumes cannot be recovered — not by us, not by anyone. That is the design, and it is irreversible. Copy it somewhere that is not this machine.

04

Open it, and trust the certificate

 AddressWho uses it
Consolehttps://<server>:4201the payroll office
Adminhttps://<server>:4301settings, users, connectors
Portalhttps://<server>:4401employees

On the first visit the browser warns that the certificate is not trusted. It is issued by a small certificate authority running inside your own install, because a public authority like Let's Encrypt cannot issue for a name on a private network — it has to reach the server from the internet, which is exactly what this deployment avoids.

Fix it once, per machine. Export the root certificate:

docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt .

Then install it as a trusted root authority:

  • Windows — double-click root.crt → Install Certificate → Local Machine → Place all certificates in the following store → Trusted Root Certification Authorities. Group Policy can push it to every machine at once.
  • macOS — open in Keychain Access → System → set to Always Trust.
  • Linux — copy to /usr/local/share/ca-certificates/ and run sudo update-ca-certificates.
  • iOS / Android — mail the file to the device and install it as a profile.

Why plain HTTP is not an option

The applications mark their session cookie Secure, and browsers discard a Secure cookie that arrived over http://. Over HTTP the login page accepts the password, redirects, and returns you to the login page — for ever, with no error anywhere.

If the server does have a public hostname, set SITE_ADDRESS to it and CADDYFILE=Caddyfile.public in .env; a normal certificate is then obtained automatically, and port 80 must be reachable for the check.

05

Connect מיכפל — optional

The connector drives מיכפל over RDP on a Windows machine on your network. In .env, set RDP_HOST to that machine's address and RDP_USER / RDP_PASS to an account that can sign into it, then:

docker compose --profile michpal up -d

One run at a time, deliberately: a Windows machine gives one interactive session per user, and two automations sharing one desktop interfere with each other in ways that are expensive to recover from.

Plan a calibration session

The automation recognises screens by their pixels, and it is calibrated against our מיכפל installation. A different version, screen resolution or company book may need recalibrating. Arrange that with us in advance rather than discovering it during a payroll run.

Updates

The install checks for a new version every ten minutes and applies it on its own. There is nothing to run.

It follows the stable channel — the release we have blessed, not whatever built most recently — so an update only happens when we decide one should. What gets restarted is deliberately narrow:

 Updates by itself
The applicationsYes — a few seconds each, one at a time
The databaseNever. A database upgrade is a data migration, and not something to do unattended at 03:00.
The מיכפל connectorNo, by default — it runs one session at a time and keeps a run's state in memory, so restarting it mid-run would end that payroll run without reporting it.

To approve every update yourself instead, set one of these in .env and restart. Either way ./install.sh update applies the current release immediately.

AUTO_UPDATE_MONITOR_ONLY=true   # reports what it would do, changes nothing
BUNDLE_VERSION=1.1.0            # pin a version; updates never fire

What the updater is allowed to do

It needs access to the Docker service on this machine, which in practice makes it as privileged as the administrator account. That is the cost of unattended security patching on a server nobody logs into. If your security policy does not allow it, use AUTO_UPDATE_MONITOR_ONLY=true and update by hand.

Running it

./install.sh status     # what is running, and the addresses
./install.sh logs       # follow everything; add a service name for one
./install.sh backup     # database + documents, into ./backups/<timestamp>/
./install.sh update     # pull a newer version and restart
./install.sh stop       # stop; your data is untouched

Backups

backup writes two files: a database dump and an archive of the stored documents. You need both — a database restored without the documents gives you an install where every employee exists and none of their files open.

Neither can be read without .env. Keep that copy somewhere else: an archive sitting beside the key that encrypts it is one theft, not two.

What leaves your network

Three things, and nothing else.

  1. Model requests, through the gateway, with identifying values replaced by placeholders and restored in the answer. Documents are read on this server — a PDF becomes text here, and only the pseudonymised text crosses. What a scan does not yield to OCR is refused rather than forwarded.
  2. Aggregate telemetry, if you enable it: counts, durations, error codes and hashed identifiers. It is checked against an allow-list immediately before sending — anything that is not a number, a timestamp, a hash or a known code is refused, so a name or an error message quoting a screen cannot pass by construction. GET /snapshot on the metrics service shows exactly what would be sent. Leave the BETTERSTACK_* values blank and nothing is reported at all.
  3. Image downloads, when you install or update.

There is no remote access channel. We cannot reach into this install; if you want us to look at something, you send us what you choose to send.

If something is wrong

SymptomWhere to look
The login page returns to itselfYou are on http://. See step 04.
"Provision a connector" on a מיכפל actionRDP_HOST is unset, or ./install.sh bootstrap has not run.
The portal shows nothing on any addressSITE_ADDRESS does not match the hostname you typed. Re-run ./install.sh bootstrap.
The model refuses a documentGATEWAY_ATTACHMENTS=block and OCR could not read the scan. Use a clearer scan, or set allow knowingly.
Reminders never send./install.sh logs scheduler — it answers 503 when a job has stopped succeeding.

Support: support@dekel.finance. Include the output of ./install.sh status and the install id from .env (METRICS_INSTALL_ID).

מדריך התקנה

הרצת מערכת השכר על השרת שלכם

מסד הנתונים, הקונסולה, הניהול, פורטל העובדים והמחבר למיכפל — הכל על חומרה בבעלותכם. בערך עשרים דקות, רובן הורדה.

מה מתקינים

עשרה קונטיינרים על מכונה אחת. ששה מהם — הקונסולה, הניהול, הפורטל, הסוכן, המתזמן ומסד הנתונים — יושבים על רשת Docker שאין לה שום מסלול לאינטרנט — לא כמדיניות אלא כעובדה במבנה הרשת. קריאה שתנסה לעקוף את השער לא תדלוף; היא פשוט לא תצליח להתחבר. רק ארבעה קונטיינרים יכולים לצאת החוצה — השער, שירות הטלמטריה, שרת התעודות ומנגנון העדכון.

ערכים מזהים מוחלפים לפני שמשהו יוצא, ומוחזרים בתשובה.

לפני שמתחילים

זיכרון8 ג׳יגה16 ג׳יגה
דיסק40 ג׳יגה פנויים100 ג׳יגה SSD

גישה יוצאת ב-HTTPS לשני שרתים בלבד, וללא שום גישה נכנסת מהאינטרנט:

  • dekelmichpalil.azurecr.io — משם מורידים את התוכנה.
  • api.anthropic.com — ספק המודל, שאליו ניגש רק השער.

אין צורך בפרטי גישה כדי להוריד את התוכנה — התמונות מוגשות באופן ציבורי ואינן מכילות קוד מקור. צריך מפתח לספק המודל (או שנספק אחד), ורק אם רוצים את המחבר — את מכונת ה-Windows שמריצה מיכפל, נגישה מהשרת הזה בפורט 3389.

01

בדיקת המכונה

הפקודה לא כותבת דבר. היא מדווחת מה חסר ועוצרת.

# הורדת הערכה
git clone https://github.com/Dekel-finance/payroll-onprem.git
cd payroll-onprem

./install.sh check

היא בודקת גרסאות של Docker ו-Compose, ליבות, זיכרון, מקום פנוי, את שני השרתים שלמעלה, ואם שלושת הפורטים פנויים. כל מה שמסומן ב-! צריך תיקון קודם.

02

התקנה

./install.sh install

ההתקנה מבקשת כתובת דוא״ל וסיסמה למנהל הראשון, ואז מדפיסה את שלוש הכתובות לפתיחה. אפשר להריץ שוב בבטחה — היא מתקנת התקנה שלא הושלמה במקום להתחיל שנייה.

ההתקנה עולה ריקה

בלי לקוחות, בלי עובדים, בלי תלושים. הרשומות שלכם נכנסות דרך תהליך הקליטה והסנכרון ממערכת השכר. התקנה שהייתה מגיעה מלאה מראש הייתה משאירה לכם שורות שצריך לזהות ולמחוק לפני שאפשר לסמוך על משהו שרואים במסך.

03

גיבוי קובץ המפתחות

ההתקנה כותבת קובץ אחד, .env, שמחזיק את הסודות של ההתקנה הזו.

לעשות את זה לפני שממשיכים

שניים מהמפתחות בקובץ מצפינים נתונים במנוחה: אחד מצפין כל מסמך של עובד, והשני הוא מה שמאפשר לקרוא מספר תעודת זהות. אם הקובץ אובד, אי אפשר לשחזר את הנתונים — לא אנחנו ולא אף אחד. זה התכנון, וזה בלתי הפיך. העתיקו אותו למקום שאינו המכונה הזו.

04

פתיחה, ואישור התעודה

 כתובתמי משתמש
קונסולהhttps://<server>:4201לשכת השכר
ניהולhttps://<server>:4301הגדרות, משתמשים, מחברים
פורטלhttps://<server>:4401עובדים

בכניסה הראשונה הדפדפן יזהיר שהתעודה אינה מהימנה. היא הונפקה על ידי רשות אישורים קטנה שרצה בתוך ההתקנה שלכם, מפני שרשות ציבורית כמו Let's Encrypt לא יכולה להנפיק לשם ברשת פרטית — היא חייבת להגיע לשרת מהאינטרנט, וזה בדיוק מה שההתקנה הזו נמנעת ממנו.

מתקנים פעם אחת, בכל מחשב. ייצוא אישור השורש:

docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt .

ואז התקנה שלו כרשות שורש מהימנה:

  • Windows — לחיצה כפולה על root.crt ← התקן אישור ← מחשב מקומי ← מקם את כל האישורים בחנות הבאה ← רשויות אישורים מהימנות. אפשר להפיץ לכל המחשבים בבת אחת דרך Group Policy.
  • macOS — פתיחה ב-Keychain Access ← System ← לסמן Always Trust.
  • לינוקס — להעתיק ל-/usr/local/share/ca-certificates/ ולהריץ sudo update-ca-certificates.
  • iOS / Android — לשלוח את הקובץ במייל למכשיר ולהתקין כפרופיל.

למה HTTP רגיל אינו אפשרות

האפליקציות מסמנות את עוגיית ההתחברות כ-Secure, ודפדפנים משליכים עוגייה כזו שהגיעה דרך http://. מעל HTTP דף ההתחברות יקבל את הסיסמה, יעביר אתכם, ויחזיר אתכם לדף ההתחברות — לנצח, בלי שגיאה בשום מקום.

אם לשרת יש שם מתחם ציבורי, הגדירו אותו ב-SITE_ADDRESS ובחרו CADDYFILE=Caddyfile.public בקובץ .env; אז תונפק תעודה רגילה אוטומטית, ופורט 80 חייב להיות נגיש לבדיקה.

05

חיבור מיכפל — לא חובה

המחבר מפעיל את מיכפל דרך RDP על מכונת Windows ברשת שלכם. בקובץ .env, הגדירו את RDP_HOST לכתובת של אותה מכונה ואת RDP_USER / RDP_PASS לחשבון שיכול להתחבר אליה, ואז:

docker compose --profile michpal up -d

הרצה אחת בכל רגע, במכוון: מכונת Windows נותנת סשן אינטראקטיבי אחד למשתמש, ושתי אוטומציות שחולקות שולחן עבודה אחד מפריעות זו לזו באופן שיקר לתקן.

לתאם מראש פגישת כיול

האוטומציה מזהה מסכים לפי הפיקסלים שלהם, והיא מכוילת מול התקנת מיכפל שלנו. גרסה אחרת, רזולוציה אחרת או ספר חברות אחר עשויים לדרוש כיול מחדש. עדיף לתאם איתנו מראש ולא לגלות את זה באמצע הרצת שכר.

עדכונים

ההתקנה בודקת אם יצאה גרסה חדשה כל עשר דקות ומחילה אותה בעצמה. אין מה להריץ.

היא עוקבת אחרי ערוץ stable — הגרסה שאישרנו, ולא מה שנבנה לאחרונה — כך שעדכון קורה רק כשהחלטנו שכן. מה שמופעל מחדש מוגדר בכוונה בצמצום:

 מתעדכן לבד
האפליקציותכן — כמה שניות לכל אחת, אחת בכל פעם
מסד הנתוניםאף פעם. שדרוג מסד נתונים הוא מיגרציית נתונים, ולא משהו שעושים ללא השגחה בשלוש לפנות בוקר.
המחבר למיכפללא, כברירת מחדל — הוא מריץ סשן אחד בכל רגע ושומר את מצב ההרצה בזיכרון, כך שהפעלה מחדש באמצע הרצה הייתה מסיימת את הרצת השכר בלי לדווח.

כדי לאשר כל עדכון בעצמכם, הגדירו אחד מאלה בקובץ .env והפעילו מחדש. בשני המקרים ./install.sh update מחיל את הגרסה הנוכחית מיד.

AUTO_UPDATE_MONITOR_ONLY=true   # מדווח מה היה עושה, לא משנה כלום
BUNDLE_VERSION=1.1.0            # נעילה לגרסה; עדכונים לא ירוצו

מה מנגנון העדכון מורשה לעשות

הוא צריך גישה לשירות ה-Docker במכונה, מה שהופך אותו בפועל למורשה כמו חשבון המנהל. זה המחיר של עדכוני אבטחה ללא השגחה על שרת שאף אחד לא מתחבר אליו. אם מדיניות האבטחה שלכם לא מאפשרת זאת, השתמשו ב-AUTO_UPDATE_MONITOR_ONLY=true ועדכנו ידנית.

תפעול שוטף

./install.sh status     # מה רץ, ומה הכתובות
./install.sh logs       # מעקב אחרי הכל; אפשר להוסיף שם שירות
./install.sh backup     # מסד נתונים + מסמכים, אל ./backups/<timestamp>/
./install.sh update     # משיכת גרסה חדשה והפעלה מחדש
./install.sh stop       # עצירה; הנתונים לא נוגעים

גיבויים

backup כותב שני קבצים: דאמפ של מסד הנתונים וארכיון של המסמכים השמורים. צריך את שניהם — שחזור של מסד הנתונים בלי המסמכים נותן התקנה שבה כל העובדים קיימים ואף קובץ שלהם לא נפתח.

אף אחד מהם אינו קריא בלי .env. שמרו את העותק ההוא במקום אחר: ארכיון שיושב ליד המפתח שמצפין אותו הוא גניבה אחת, לא שתיים.

מה יוצא מהרשת שלכם

שלושה דברים, ולא יותר.

  1. בקשות למודל, דרך השער, כשערכים מזהים מוחלפים בסימנים ומוחזרים בתשובה. מסמכים נקראים על השרת הזה — קובץ PDF הופך לטקסט כאן, ורק הטקסט המוסווה חוצה. מה שסריקה לא מוסרת ל-OCR נדחה ולא מועבר.
  2. טלמטריה מצטברת, אם תפעילו אותה: מונים, משכי זמן, קודי שגיאה ומזהים מגובבים. היא נבדקת מול רשימת היתר בדיוק לפני השליחה — כל דבר שאינו מספר, חותמת זמן, גיבוב או קוד מוכר נדחה, כך שבמבנה אין דרך ששם או הודעת שגיאה שמצטטת מסך יעברו. GET /snapshot בשירות המדדים מראה בדיוק מה היה נשלח. אם משאירים את BETTERSTACK_* ריק, לא מדווח דבר.
  3. הורדות תמונות, בהתקנה או בעדכון.

אין ערוץ גישה מרחוק. אנחנו לא יכולים להיכנס להתקנה הזו; אם תרצו שנסתכל על משהו, אתם שולחים לנו את מה שאתם בוחרים לשלוח.
